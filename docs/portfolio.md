# Portfolio (MEXC)

**Route:** `/portfolio` (the Portfolio view of the account area; `/profile` and `/profile/edit-profile` are the Edit view of the same page) and a "Your MEXC" box on every coin page, above Alerts.
**Status:** built 2026-10-16, **live** (deployed 2026-10-16). Real data only on the live server, because the MEXC key is linked to the live server's IP and Malaysian ISPs block MEXC by DNS. Locally it is tested with demo data.
**Source:** `app/services/mexc_service.py` (MEXC reads, caching, cost math), `frontend/frontend/state/portfolio_state.py`, `frontend/frontend/components/portfolio_page.py`, styles `.pf-*` in `frontend/assets/styles.css`, table `portfolio_costs` (`app/models/portfolio_cost.py`, migration `c4e6a8b0d2f3`), tests `tests/test_mexc_service.py` + `tests/fixtures/mexc_demo.json`.

## Features

<details><summary><strong>Read-only connection and who can see it</strong></summary>

- The key is a MEXC API key with only Spot **View Account Details** + **View Order Details** ticked, linked to the server's IP (an unlinked key expires after 90 days). `MEXC_API_KEY` / `MEXC_API_SECRET` live only in the server's gitignored `.env`.
- On top of the key's own permissions, `mexc_service._get` signs only GET requests to `_READ_PATHS` (`/api/v3/account`, `/api/v3/openOrders`, `/api/v3/myTrades`). Any other path raises before a request is sent. Nothing in the code can trade, cancel, withdraw or transfer.
- The key and secret are never logged, put in an error, or sent to the browser. Network errors are re-raised `from None` as `MexcError` with a plain message, so no signed URL reaches `logs/error.log`. MEXC error codes map to a fix (e.g. 700006 = "server IP not linked to the key"); any other code shows only "MEXC API error (code N). Details are in the server log." because MEXC's own text can contain the server's IP, and the raw code + message are written to the server log (`mexc_service._log`) instead. Requests use HTTPS only, a 4 s connect / 10 s read timeout and `allow_redirects=False` (a signed request and its API-key header are never forwarded to another address).
- **Nothing stays in the session after logout:** `PortfolioState._clear_portfolio` resets every `pf_*` / `coin_mexc_*` var (found by prefix, so a new var is covered automatically). `CoinState.logout` calls it (through `get_state`), and every loop / refresh also calls it the moment the viewer check fails (logged out, or another account in the tab). Checked end to end in a browser: after logout and after a reload no server frame contains the balances. **Rules for this state:** a public var holds only display strings (never a raw MEXC reply, an id or a credential: `_order_view` no longer sends MEXC's order id), and any raw MEXC data a feature needs must live in a `_`-prefixed (backend-only) var and be emptied in `_clear_portfolio`.
- Only logged-in accounts listed in `MEXC_VIEWER_EMAILS` (comma-separated) get any data. Empty = nobody. Every loop and event checks `mexc_service.can_view(user_email)` on the server. Anyone else sees "Exchange portfolios are not available for this account", and the coin-page box is hidden.
</details>

<details><summary><strong>Dashboard (/portfolio)</strong></summary>

- **Header:** "MEXC Spot · read-only" badge, a "Demo data" badge when the fixture is used, the last successful read time (Kuala Lumpur), and a refresh icon (`refresh_portfolio`, forces a fresh read).
- **Total balance** (all balances x price) with its **24h change** (sum of amount x (price - 24h open)). Four tiles: **Unrealized P/L** (only coins with a known average buy price), **Stablecoins** (and their share of the wallet), **In open orders** (value of locked balances, number of open orders), **Coins held** (plus "small balances": holdings under $1 are folded into one line).
- **Allocation ring:** CSS `conic-gradient` of the 6 biggest holdings + "Others" (Radix step-9 colours, readable in both themes), legend with percentages.
- **Holdings table:** coin (logo + link to `/coins/<slug>` when the site knows the ticker; ties go to the best CMC rank), amount (and how much is in orders), live price (`_fmt_usd`), 24h %, value, average buy price, P/L in $ and %, share bar. Biggest value first.
- **Open orders:** pair, Buy/Sell, type (Limit, Post-only, Stop-limit, Take-profit...), price, trigger price, amount and % filled, remaining value, distance from the market price, time placed.
- **Recent fills:** the 50 latest trades on the coins you hold (time, side, price, amount, total, fee), **5 rows per page** with the site's pager (first / previous / "Page 1 of N" / next / last; hidden when there is one page). Only the current page is sent to the browser (`pf_trades`); the full formatted list stays in the backend-only `_pf_trades_all`, the page number survives the 10 s refreshes and is clamped if the list shrinks (`PortfolioState._show_trades_page`).
- Wide tables scroll inside their card, never the page (checked 1440 / 834 / 375 px, dark and light, no console errors).
</details>

<details><summary><strong>Balance chart (card under Allocation + popup)</strong></summary>

- MEXC keeps no balance history, so the server records it: a lifespan task in `frontend.py` (`_mexc_balance_recorder`) calls `portfolio_history_service.record_from_mexc()` every 5 minutes, 24/7, into `portfolio_balance_history` (migration `d6f8b0c2e4a6`). Only fresh, real readings are saved: never demo data, never the last-good numbers kept on screen while MEXC is failing. History starts at the first deploy of this feature (2026-10-16); nothing is estimated for the time before.
- **Card** (`portfolio_page.py::_balance_card`, under Allocation in the right column): "Total balance · 7D", the current total, the 7-day change, and a blue area line (Recharts, built into Reflex, free). The last point is the live total, so the line moves with every 10 s refresh. Until two readings exist it says it is collecting data.
- **Click -> centred popup** (`_balance_popup`, up to 960 px wide) that opens on **Full Chart**, with **24H / 7D / 1M / Full Chart** buttons, axes in $, a tooltip with the exact time and value, the range's change, high and low, and "Recording since …". Ranges are bucketed to the last reading per bucket (24H: 5 min, 7D: 30 min, 1M: 1 h, Full: sized to ~1,000 points), read through a 60 s shared cache (`portfolio_history_service.series`).
- **Follows the MYR / USD buttons** (2026-10-16): with MYR the card, the popup header, the y-axis, the tooltip and high/low are in RM, every reading converted at today's live rate (the same rate as the Total balance card, shown under the popup chart as "In MYR at today's rate: …"; past readings are not converted at the rate of their own day). Switching redraws from the readings already held (`_pf_hist_card_rows` / `_pf_hist_popup_rows`, backend-only), with no database read. Tests: `tests/test_portfolio_charts.py`.
</details>

<details><summary><strong>MYR / USD switch on the Total balance card</strong></summary>

- The "Total balance" row is a space-between row: the label on the left, **MYR** and **USD** buttons on the right (`portfolio_page.py::_currency_toggle`, `.pf-cur*` in `styles.css`). **MYR is the default (changed 2026-10-18; it was USD)**; the choice lasts for the session and goes back to MYR on logout. If no live MYR rate can be had the card falls back to USD with a message.
- **MYR converts this card's money amounts** (total balance, 24h change, unrealized P/L, stablecoins, value in open orders, the small-balances note: `portfolio_state._summary_view`) **and the balance chart** (card + popup, see above). Percentages, counts and every table below (holdings, open orders, fills) stay in USD.
- A small line under the 24h pill shows the rate and where it came from, e.g. "1 USD = 4.0800 MYR · Yahoo Finance · live" (or "quote of 16 Oct 03:49 (KL)" when the last quote is older than 15 min).
- **The rate is live from the forex market**, not a fixed number (`app/services/fx_service.py`, no key, no cost): Yahoo Finance's USD/MYR quote (polled every 60 s) plus two daily references, ExchangeRate-API open data and the European Central Bank via Frankfurter (polled hourly). A quote far (> 2%) from the others' median is dropped, and the freshest of the rest wins. A source that fails is skipped for 5 min, and a rate is kept up to 72 h if every source fails. With no rate at all, the MYR button keeps the card in USD with "The live MYR rate is unavailable right now". One shared cache for every viewer; the 10 s dashboard refresh asks for the rate only while MYR is shown. Limits: Yahoo's MYR quote has only 2 decimals and can sit still for a while in quiet hours (the line then shows the quote's time); true tick-by-tick MYR needs a paid forex API key.
- Tests: `tests/test_fx_service.py`. Checked in a browser (demo data, real rate): label left / buttons right on one row at 1440 / 834 / 375 px in dark and light, MYR total = USD total x the shown rate, tables unchanged, survives a refresh cycle, USD restores; with every source blocked the card stays USD with the message.
</details>

<details><summary><strong>Prices, refresh and caching</strong></summary>

- Prices come from MEXC's own public 24h ticker list (`/api/v3/ticker/24hr`, one call): the USDT pair, else the USDC pair; stablecoins without a pair count as $1.
- One key = one account, so every viewer shares one cache: balances + open orders at most every 20 s (`ACCOUNT_TTL`), prices every 10 s, a coin's trade history every 10 min or as soon as its balance changes (an order filled). The page redraws every 10 s (`portfolio_loop`). It runs while the tab is in the account area, because the sidebar swaps Portfolio/Edit in the browser without a server navigation.
- Open orders: one call for all symbols if MEXC accepts it, else one call per coin held (worth >= $1 or with coins locked). In the per-coin case, USDT locked in buy orders on coins you don't hold can't be listed. The page then says how much and points to that coin's page, where the box asks MEXC for that coin directly.
- On a MEXC error the last good data stays on screen with an amber message above it.
- **Rate limits (HTTP 429, or code 429 in the body):** every MEXC request is paused (`mexc_service._rate`): 20 s the first time (longer if MEXC sends `Retry-After`), doubling on each further 429 up to 5 min, reset by the next good reply. The pause is checked inside `_get` before anything is sent, so the refresh icon (`force=True`) cannot skip it; the page shows "MEXC rate limit reached. Waiting about N s…" and the event is logged as a warning.
- **A failing cycle never stops the loops:** `portfolio_loop` / `coin_mexc_loop` (and the refresh icon and cost saving) catch any unexpected network, database or reply error, write the detail to the server log, show "MEXC data could not be refreshed just now. Retrying shortly." and carry on with the next cycle, keeping the last data on screen.
</details>

<details><summary><strong>Average buy price and profit/loss</strong></summary>

- Worked out from MEXC's trade history of the account (the API keeps about one month), average-cost method (`average_cost`): buys add their USDT cost (a USDT fee adds to it, a fee paid in the coin reduces the coins received), and sells remove coins at the running average.
- Used only when the history covers at least 98% of the holding and no sell was bigger than the coins seen. Otherwise the coin shows "—" (bought earlier or deposited from elsewhere), and the hero notes how many coins lack a price.
- A hand-typed average (`portfolio_costs`, `mexc_service.set_cost`) wins over the history and is labelled "set by you". **The pencil icon that opened the dialog was removed on request (2026-10-16)**, so there is currently no button to enter one; averages saved earlier still apply, and the dialog / events (`open_cost_dialog`, `save_cost`, `clear_cost`) are still in the code, unreachable, ready to be wired to something else.
</details>

<details><summary><strong>Coin page: "Your MEXC" box (above Alerts)</strong></summary>

- Viewers only. Shows how much of the coin you hold, its value, average buy price and P/L. Below that, every open order on the coin (Buy/Sell, type, price, amount, trigger, distance from the market price), including a buy order on a coin you don't hold yet. "No open MEXC orders for this coin." when there are none. A "Portfolio →" link goes to `/portfolio`.
- **Your lines on the main chart** (2026-10-16, replaced the earlier mini chart in this box): on a coin you hold or have an open order on (MEXC viewers only), the main chart area opens on **"My lines"**: a TradingView **Lightweight Charts** view (Apache-2.0, free and permanent, self-hosted at `frontend/assets/vendor/lightweight-charts-4.2.3.standalone.production.js`, loaded only when shown, with TradingView's attribution logo as its licence asks) of the coin's MEXC USDT pair, the same size as the widget, with pan and zoom. Lines: **average buy price blue**, every **limit order green**, every **stop / stop-loss order red and dashed** at its trigger price, each labelled on the price axis; the scale always keeps every line in view. A bar above the chart (`portfolio_page.py::coin_chart_lines_bar`) has a **My lines / TradingView** switch (TradingView brings back the normal widget with its indicators and drawing tools), timeframe buttons **15m / 1h / 4h / 1D / 1W** (MEXC candles, last 300, read by the server via `mexc_service.klines`, cached 60 s per pair and timeframe) and the line legend. Why a separate chart: the TradingView widget is a cross-site iframe whose URL takes no drawings, and a page cannot draw inside another site's frame. Coins with nothing of yours, coins without a MEXC USDT pair, and every other visitor keep the TradingView widget exactly as before. Drawn by `assets/mexc_lines_chart.js` from the chart's `data-candles` / `data-lines` / `data-fit` attributes (refit when the coin or timeframe changes, restyled on a light/dark switch). State: `coin_mexc_has_lines`, `coin_mexc_chart_mode`, `coin_mexc_interval` (reset on logout).
- `coin_mexc_loop` refreshes it every 15 s and follows the coin when the tab moves to another coin page.
</details>

<details><summary><strong>Telegram: /portfolio</strong></summary>

- `/portfolio` (also in the bot's menu and `/view_all_command`) replies with: total balance, 24h change, total profit/loss, stablecoins and the value held in orders, every holding (amount, live price, value, average buy, P/L), small balances, and every open order (Buy/Sell, type, price, trigger price for stop orders, amount, distance from market). Prices go through the site's `_fmt_usd` (registered into the bot by `frontend.py`).
- **Owner only:** the chat must be linked to an account (Notifications > Connect Telegram) AND that account's email must be in `MEXC_VIEWER_EMAILS`. An unlinked chat gets the usual "not connected" line; any other linked account gets "Portfolio is not available for this account." and MEXC is not called at all. A MEXC error shows only the safe message (never the key, secret or IP).
- Telegram messages are capped at 4096 characters: longer ones are cut at a line end under 3900 (`telegram_notify_service.format_portfolio`), never inside an HTML tag.
- The bot only polls on the live server (`TELEGRAM_BOT_POLLING=true` there), so the command can't be tried locally; it is covered by `tests/test_telegram_portfolio.py`.
</details>

## Solana deposit address in the Total balance card (2026-10-20, **local only, not deployed**)

The empty space at the bottom of the Total balance card now holds the account's own **Solana deposit address** from MEXC: label + network badge (`Solana(SOL)`), the address in a monospace box and a **Copy** button (clipboard + "Solana address copied" toast). Read through `mexc_service.deposit_address("SOL")`: a signed **GET** `/api/v3/capital/deposit/address?coin=SOL` (added to `_READ_PATHS`; it only returns an address the account already has, the POST that creates one is never called, and the module still has no write call). MEXC lists one address per network, so only the entry whose network is Solana is used (not the BEP20 one). **MEXC can change a deposit address by itself**, so it is re-read about every minute while the page is open (`DEPOSIT_TTL` = 60 s) and at once by the page's refresh icon; if MEXC hands out a different address than the one seen before, the card shows an amber "MEXC changed this address on <time> (KL). Use this one." and the change is logged (the note lasts until the server restarts). A refusal (e.g. the API key lacks the wallet / deposit permission, or MEXC has no SOL address yet) is remembered for 5 minutes, and when an address was already read the last good one stays shown with the reason underneath and shown in amber inside the card as "The deposit address could not be read from MEXC: ..." while the rest of the page keeps working. It is part of the `portfolio()` snapshot (`deposit_sol`), so it is only ever sent to MEXC viewer emails. Demo data (`tests/fixtures/mexc_demo.json`, `depositAddress`) has a made-up address. Real data only on live (the key is linked to the server's IP): if the live key was made with only View Account Details + View Order Details, MEXC may answer with a permission error until the key gets the deposit-address permission under MEXC > API Management. Tests: `tests/test_mexc_service.py`.

**Permission needed (found 2026-10-20 on live):** the balance / order reads work with Spot "View Account Details" + "View Order Details", but MEXC answers the deposit-address call with "no permission" (code 700007) until the key also has the read-only **"View Deposit/Withdrawal Details"** permission (third-party MEXC guides list it as "Withdraw: View Deposit/Withdrawal Details"; MEXC's own docs do not name the scope, so this is the best match, not a confirmed mapping). Never tick Withdraw or Trade. The card's error text says this.


## B / S markers on the coin page "My lines" chart (2026-10-21)

The lines chart (coin page, MEXC viewers) now also draws **your own buys and sells** like MEXC's chart: a green **B** circle for every buy and a red **S** circle for every sell, placed on the candle of the fill at the fill's price (fills of the same side in one candle share one circle at their average price). It appears for a coin you **hold** or **traded before** (the chart view is offered when the coin has lines or fills, plus candles); a coin you never traded keeps the plain TradingView chart. Data: `mexc_service.coin_trades(asset)` (signed read of `/api/v3/myTrades` for `<COIN>USDT`: uses the trades already cached for holdings, else one on-demand fetch cached 10 minutes; a refusal or a pair MEXC does not have is remembered 60 s), sent to the chart as `data-trades` (`[[time s, "B"|"S", price, qty], ...]`), drawn by a Lightweight Charts series primitive in `assets/mexc_lines_chart.js` (pan / zoom follow the chart). They are kept out of the Portfolio page's Recent fills table. **Limit:** MEXC's API only keeps about the **last month** of trades, and the circles only show for the candles on the chart (500 of the chosen timeframe, MEXC's maximum: about 20 days on 1h, longer on 4h / 1d), so older buys / sells do not appear. Demo data has SUI (held) and ADA (traded and closed). Tests: `tests/test_mexc_service.py`, `tests/test_portfolio_charts.py`.

**Stale-script fix (2026-10-21):** the first live deploy showed no B / S circles although the server returned the fills (77 for FET). Cause: our own scripts in `frontend/assets` are served with `cache-control: max-age=14400` (4 hours, browser and Cloudflare), so a visitor who had loaded `mexc_lines_chart.js` earlier that day kept running the OLD copy that ignores `data-trades`. All our scripts are now linked as `/<file>.js?v=<file modified time>` (`frontend.py::_asset`), so every deploy that changes a script changes its URL and it is fetched fresh; candles per chart went from 300 to 500. Test: `tests/test_asset_urls.py`.
